# Professional Portfolio Website – Project Proposal

## 1. Project Description

For my project, I plan to continue developing and expanding my professional portfolio website. I originally started the portfolio during a previous summer course using HTML and CSS, and I have now moved the project into its own GitHub repository so I can continue improving it throughout this course.

The website will serve as a central location where visitors can learn about my professional background, education, technical skills, work experience, and projects. Instead of being only a digital version of a resume, I want the site to show examples of the work I have completed and the skills I am continuing to develop. Visitors will be able to move between sections of the site and view information about me, my experience, technical projects, and ways to contact me.

This project matters because my professional experience covers several different areas, including construction and building inspection, technology, and my current education in Computing Applications. As I continue moving toward a career in technology and cybersecurity, I want a portfolio that better represents both my existing professional experience and the technical skills I am developing.

The intended audience is potential employers, recruiters, instructors, classmates, and professional contacts. The website will give them one location where they can see my background and examples of my work without relying only on a traditional resume.

## 2. Feature Plan

### Project 01 – Week 05

For the first prototype, I plan to focus on creating a functional and organized version of the portfolio.

* **Homepage:** A main landing page that introduces who I am and gives visitors a quick overview of my professional and technical background.
* **Navigation:** A consistent navigation menu that allows visitors to move easily between the major sections of the website.
* **About Section:** A section describing my professional background, education, interests, and current career direction.
* **Skills Section:** A section displaying the technical and professional skills I have developed.
* **Projects Section:** A section that highlights selected school, web development, and technical projects with short descriptions.
* **Contact Information:** A section that gives visitors a way to connect with me through professional contact methods and links.
* **Responsive Layout:** Basic responsive CSS so the website remains usable on desktop computers, tablets, and mobile devices.
* **Consistent Design:** Common fonts, spacing, headings, and page styles throughout the site.

### Project 02 – Week 08

For the final MVP, I plan to improve the original prototype and add features that make the site more polished and interactive.

* **Expanded Project Gallery:** Add additional projects with descriptions, screenshots, technologies used, and links to GitHub repositories when available.
* **Project Filtering:** Allow visitors to organize or filter projects by categories such as web development, cybersecurity, or professional work.
* **Improved Responsive Design:** Refine the layout for different screen sizes and improve the mobile navigation experience.
* **JavaScript Interactivity:** Add appropriate JavaScript features such as menu controls, project filtering, or other interactive page elements.
* **Resume Access:** Provide visitors with an easy way to view or access my current professional resume.
* **Improved Accessibility:** Review headings, image alternative text, contrast, navigation, and other accessibility features.
* **Visual Improvements:** Improve the overall appearance of the portfolio with better spacing, project cards, images, and consistent styling.
* **Final Testing:** Test navigation, links, layout, and functionality across multiple browsers and screen sizes before publishing the final version.

## 3. Tools and Technologies

### Code Editor and Development Environment

I plan to use **Visual Studio Code** as my primary development environment. I am already familiar with VS Code and have been using it to edit my HTML and CSS files. I will also continue using the **Live Server** extension because it allows me to preview changes locally while I am developing the site. I chose this setup because it gives me direct access to the code instead of hiding the development process behind a website builder.

### Framework, Platform, or Approach

I plan to build the website primarily with **HTML, CSS, and JavaScript** rather than using a website builder or a large framework. This approach gives me more control over the project and allows me to practice the core web development skills covered in the course. Since this is a portfolio site rather than a large web application, I do not believe a more complicated framework is necessary for the current scope of the project.

### Hosting and Deployment

I plan to use **GitHub** for version control and **GitHub Pages** to publish the website. The project is already stored in a dedicated GitHub repository, so using GitHub Pages will allow the published website and the source code to remain connected. It will also give me experience working through a normal development process of making changes locally, committing those changes, pushing them to GitHub, and deploying the finished site.

### AI Tools

I plan to use **ChatGPT** as a support tool during development. I may use it to help explain HTML, CSS, or JavaScript concepts, troubleshoot errors, brainstorm possible solutions, and review my writing. I want to use AI as a learning and troubleshooting resource rather than depending on it to build the entire project for me. This will allow me to understand the code I am adding and make decisions about whether a suggested solution actually fits my project.

### Other Tools

I will use **GitHub Desktop** to manage commits and changes between my local project files and the GitHub repository. I chose GitHub Desktop because its visual interface makes it easier for me to verify exactly which files have changed before I commit and push them. I may also use browser developer tools to inspect page layouts, test responsive designs, and troubleshoot HTML, CSS, and JavaScript problems.

## 4. Risks and Unknowns

One risk is **project scope**. There are several features I would eventually like to include in the portfolio, but trying to build all of them at once could make the project larger than what can realistically be completed during the course. I plan to control this by treating the Project 01 features as the required foundation and only adding Project 02 features after the main site is working correctly.

Another unknown is **JavaScript interactivity**. I am comfortable working with the existing HTML and CSS project, but some of the interactive features I want to add will require additional JavaScript. Features such as project filtering and mobile navigation may require techniques that I have not used before.

A third risk is **responsive design**. A layout that looks correct on my desktop may not automatically work well on phones or tablets. I will need to test the website at several screen sizes and make adjustments as the project develops.

The final unknown is how much the **design of the portfolio may change as additional projects are added**. The current structure works for the content I already have, but the Projects section may need to be redesigned as the number and variety of projects increase. I plan to keep the structure flexible so that new projects can be added without requiring the entire website to be rebuilt.
