# CS 4303 – Project 02 Reflection

## Decisions I Made

One of the biggest decisions I made during this project was deciding what the portfolio was actually supposed to represent. At first, it was mostly a professional website that showed my work history, education, and some of the projects I had completed in school. As I continued working on it, I realized that I wanted it to do more than document where I have already been. I wanted it to show where I am trying to go.

That changed the direction of the portfolio. Cybersecurity, Digital Forensics and Incident Response, Linux, and technical projects became more important as the project developed. I still kept my previous professional experience because it is part of who I am and shows skills like technical analysis, problem-solving, documentation, and responsibility, but I started putting more emphasis on the technical work I am building now.

Another important decision was controlling the scope. I considered adding a dark/light theme, more animations, search, modals, and several other interactive features. Eventually, I decided that adding more JavaScript just to say the site had more JavaScript was not a good reason to add something. I focused on features that actually improved the site, such as project filtering and the contact form.

## What Worked

The overall structure of the portfolio worked well. Having separate Home, About, Projects, and Contact pages gave me a good foundation and made it easier to continue expanding the site without completely redesigning it every time I added something.

I am especially happy with the Projects page. The filtering system was one of my first meaningful uses of JavaScript on the site, and it made the page more useful instead of just being a long list of projects. Adding my DFIR Field Guide and DFIR First Steps work also made the portfolio feel much more connected to what I actually want to do professionally.

The contact form was another part that worked better than I originally expected. I used Formspree with JavaScript so someone can actually send me a message through the website. Building in validation and success or error feedback made it feel like a real feature instead of just a form that looks functional.

GitHub Pages also worked well for this project. Being able to make changes locally, test them, commit them, push them to GitHub, and then see the same changes on a live website helped me understand the complete development process much better.

## What I Would Do Differently

If I started this project over, I would plan the mobile experience earlier. The site works on smaller screens, but I originally treated responsive design more like something to fix after the desktop version was working. I would design both experiences together from the beginning.

I would also organize my CSS more carefully from the start. As the portfolio grew, the stylesheet grew with it. It still works, but I now understand why planning reusable classes and keeping the stylesheet organized becomes more important as a project gets larger.

I would also create a testing checklist earlier. Toward the end of the project I started thinking more systematically about links, forms, mobile layouts, accessibility, and browser testing. That should have been part of the process from the beginning instead of something mainly associated with final delivery.

## What I Learned

The biggest thing I learned is that building a website is not just writing HTML, CSS, and JavaScript. A lot of the work is making decisions about what belongs, what does not belong, how information should be organized, and whether a feature actually helps the person using the site.

I also became much more comfortable using Git and GitHub as part of an actual workflow instead of treating them as just places to submit assignments. I have gotten used to making a change, testing it, committing it, pushing it, and checking the deployed version.

I learned a lot from troubleshooting too. Things did not always work the first time, especially when I started adding JavaScript and connecting separate projects and repositories. Fixing those problems taught me more than if everything had worked immediately.

Most importantly, this project started feeling like something I actually want to keep after the class is finished. It is no longer just a class assignment. I can continue adding cybersecurity labs, DFIR projects, Linux work, and other technical projects as I build experience. That makes the portfolio useful beyond this course, which is probably the part of the project I am most satisfied with.
