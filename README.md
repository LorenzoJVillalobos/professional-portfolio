# Professional Portfolio

## 1. What is this?

This project is my professional portfolio website. It brings together my professional experience, education, technical skills, coursework, web development projects, and growing experience in cybersecurity and digital forensics.

The site includes multiple pages covering my background, current projects, professional experience, and contact information. It also includes an interactive project filter that allows visitors to sort projects by categories such as Web Development, Cybersecurity & DFIR, IT / Home Lab, Professional Experience, and Coursework.

The portfolio also includes a functional contact form and links to my GitHub and LinkedIn profiles. It is designed to show both the experience I already have and the technical direction I am continuing to build toward.

## 2. Why does it exist?

I created this portfolio to build a professional online presence while documenting my transition into technology and cybersecurity.

My background includes military service, construction, plumbing, building inspections, plan review, and technical problem-solving. I am now completing my degree in Computing Applications and developing skills in web development, Linux, cybersecurity, digital forensics, and incident response.

The goal of the portfolio is to connect my previous professional experience with the technical work I am doing now and provide one place where employers, instructors, classmates, and other professionals can see that progression.

It also gives me a place to show what I am learning through actual projects instead of simply listing skills on a résumé.

## 3. What tools did I use?

* **HTML** — Used to create the structure and content of each page using semantic web elements.
* **CSS** — Used to create the visual design, responsive layouts, typography, navigation, project cards, forms, and mobile-friendly formatting.
* **JavaScript** — Used to add interactivity, including the project-category filtering system and contact-form behavior.
* **Formspree** — Used to make the contact form functional so visitors can send messages through the website.
* **Visual Studio Code** — Used as my primary development environment for writing and editing the website files.
* **Live Server** — Used to preview and test changes locally while developing the site.
* **Browser Developer Tools** — Used to test responsive layouts, inspect CSS, troubleshoot JavaScript, and check the site at different screen sizes.
* **Git** — Used for version control so I can track changes as the portfolio develops.
* **GitHub** — Used to store the project repository and document the development history through commits.
* **GitHub Pages** — Used to deploy the website publicly so anyone with the URL can view it.
* **GitHub Desktop** — Used to help manage commits and synchronize changes between my local project and GitHub.
* **ChatGPT** — Used as a learning, troubleshooting, and development assistant while working through HTML, CSS, JavaScript, responsive design, debugging, content organization, and ideas for improving the site. I used AI as a tool to help me understand and improve my work rather than as a replacement for understanding the code.

I chose these tools because they provide a practical way to build, test, manage, and deploy a static website while also giving me experience with tools and workflows commonly used in web development.

## 5. What Changed from P01 to P02

The biggest change from P01 to P02 was moving the portfolio from a good foundation toward something that better represents me professionally and the direction I am trying to go.

One of the most important additions was the functional contact form. Instead of only displaying an email address, visitors can now send a message directly through the website. I connected the form to Formspree and used JavaScript to handle submission, validation, and success or error messages.

I also expanded the Projects page to better represent my current technical interests. The portfolio now includes my DFIR Field Guide and DFIR First Steps work, which makes cybersecurity, digital forensics, incident response, research, and technical writing much more visible. This was important because I did not want the portfolio to focus only on where I have worked in the past. I wanted it to also show where I am going.

The content throughout the portfolio has also been refined to create a clearer connection between my professional background and my developing technical skills. My previous experience in inspections, plan review, construction, and public service remains important, but the portfolio now places more emphasis on technical analysis, problem-solving, cybersecurity, Linux, web development, and digital investigations.

I also improved the professional contact information by adding my GitHub and LinkedIn profiles so visitors have additional ways to view my work and professional background.

Not every feature I considered for P02 made it into the final project. I decided not to add features such as a dark/light theme, modals, search tools, additional animations, or other JavaScript controls simply to make the site more complicated. I would rather have a smaller number of features that serve a real purpose and work correctly than add features just to increase the technology used.

The biggest change between P01 and P02 is not necessarily the number of features. The portfolio now has a clearer purpose. It is becoming a professional record of my transition from my previous technical career into computing, cybersecurity, and Digital Forensics and Incident Response.
